# Polyclaw 日本語化 スタイルガイド

## はじめに
- 本ガイドの目的は、日本語化作業における文体・記号・表記の一貫性を確保することです。
- 用語の対応は別途 `glossary.md` を参照してください。
- すべての PR は本ガイドに準拠していることを確認してください。
- 大前提は「ユーザに見えるものは日本語、開発者しか見ないものは英語」です。
- UI、通知、エラーメッセージ、LLM 応答、LLM プロンプトはユーザ可視テキストとして扱います。
- コード識別子、ログキー、設定キー、API パス、テスト名は開発者向けテキストとして扱います。
- ユーザが読む可能性がある文字列は、日本語化対象です。
- 開発者だけが読む内部実装は、英語のままで構いません。
- 英語の内部文字列が UI に露出する場合は、日本語化してください。
- 本ガイドと `glossary.md` が衝突する場合、用語は `glossary.md`、文体・記号は本ガイドを優先してください。

## 1. 基本文体

### 1.1 ですます調
- ユーザ可視テキストはすべて「ですます調」で書いてください。
- LLM プロンプト内も「ですます調」で記述してください。
- LLM プロンプトの口調は、LLM の応答口調に直接影響します。
- 例外は、ボタンラベル、メニュー項目、表ヘッダーです。
- 例外では、体言止めまたは動詞単独を使用できます。
- 「だ・である調」は使用しないでください。
- 「タメ口」や過度にフランクな口調は使用しないでください。
- 技術プロダクトとして、簡潔で落ち着いた丁寧語を使用してください。
- 「ございます」「いたします」などの過度な敬語は避けてください。
- 説明文では、短く自然な「です」「ます」を優先してください。
良い例:
```text
Azure リソースを作成します。
保存しました。
設定を確認してください。
```
悪い例:
```text
Azure リソースを作成する。
保存したよ。
設定をご確認いただけますでしょうか。
```

### 1.2 体言止め（例外用途）
- ボタンラベルでは体言止めまたは動詞単独を使います。
- メニュー項目では短い名詞を使います。
- 表ヘッダーでは名詞句を使います。
- 見出しでは体言止めを使用できます。
- 通知本文では体言止めを避け、文として完結させてください。
- ボタンラベルには句点を付けません。
- メニュー項目には句点を付けません。
- 表ヘッダーには句点を付けません。
例:
```text
ボタンラベル: 保存、キャンセル
メニュー項目: 設定、ログアウト
表ヘッダー: 名前、状態、最終更新
```

### 1.3 命令文の扱い
- システムからユーザへの指示は「〜してください」と書いてください。
- エラーメッセージ内の指示も「〜してください」と書いてください。
- LLM プロンプト内のシステムからエージェントへの指示も「〜してください」と書いてください。
- 命令形の「〜しろ」「〜せよ」は使用しないでください。
- 強い禁止は「〜してはいけません」または「絶対に〜しないでください」と書いてください。
- 危険操作では、禁止理由を短く添えてください。
- ユーザを責める表現は避けてください。
- 対処できる操作を明確にしてください。
良い例:
```text
接続を確認してください。
もう一度お試しください。
ユーザに見える文字列は日本語で書いてください。
秘密情報を出力してはいけません。
```

### 1.4 人称・敬語
- LLM の自称は「私」を使用してください。
- ユーザの呼称は基本的に省略してください。
- 必要な場合のみ「あなた」を使用してください。
- 「お客様」「ご主人様」「君」「ユーザー様」は使用しないでください。
- 敬語は丁寧語に固定してください。
- 尊敬語と謙譲語は原則として使用しないでください。
- 技術的なエラーでは、謝罪より原因と対処を優先してください。
- 「申し訳ございません」「恐れ入りますが」などの過度な表現は避けてください。
良い例:
```text
設定を保存しました。
私はこの操作を実行できません。
保存できませんでした。接続を確認してください。
```

## 2. 句読点・記号

### 2.1 句読点
- 句点は全角の「。」を使用してください。
- 読点は全角の「、」を使用してください。
- カンマ「，」は使用しないでください。
- ピリオド「．」は使用しないでください。
- 日本語文の末尾は原則として「。」で閉じてください。
- ボタンラベル、見出し、表ヘッダーには句点を付けません。
- 箇条書きでも、文として完結する場合は「。」を付けます。
- 短い名詞句だけの箇条書きでは、句点を省略できます。
良い例:
```text
設定を保存しました。
Azure CLI が見つかりません。
```
悪い例:
```text
設定を保存しました.
Azure CLI が見つかりません，
```

### 2.2 括弧
- 和文中では全角の「（）」を使用してください。
- 和文中では全角の「【】」を使用できます。
- 和文中では全角の「「」」を使用してください。
- 英文中では半角の `()` を使用してください。
- コード中では半角の `()`、`[]`、`{}` を使用してください。
- ファイルパス、コマンド、API パスでは半角記号を維持してください。
- Markdown リンク構文では半角 `[]()` を使用してください。
- 和文の説明内にコードを入れる場合は、コードの外側で全角括弧を使用してください。
良い例:
```text
Azure リソース（リソースグループ単位）を作成します。
設定ファイル（`.env`）を確認してください。
```
悪い例:
```text
Azure リソース(リソースグループ単位)を作成します。
```

### 2.3 感嘆符・疑問符
- ユーザ可視テキストでは全角の「！」と「？」を使用してください。
- API エラーメッセージなどの技術的文脈では、半角 `!` と `?` を許容します。
- 感嘆符は多用しないでください。
- 感嘆符を連続して使わないでください。
- 疑問文では全角「？」を使用してください。
- 確認ダイアログでは、原則として「？」で閉じます。
- エラー文では、感嘆符より平叙文を優先してください。
- 不安をあおる表現は避けてください。
良い例:
```text
保存できませんでした。もう一度お試しください。
本当に削除しますか？
本当に削除してもよろしいですか？
```

### 2.4 引用符
- 和文中では全角の「」を使用してください。
- 和文中で引用をネストする場合は『』を使用してください。
- 英文中では半角の `"` または `'` を使用してください。
- コード中では言語の構文に従って半角引用符を使用してください。
- UI ラベルを本文で示す場合は「」で囲んでください。
- コマンド、ファイル名、識別子はバッククォートで囲んでください。
良い例:
```text
「保存」を選択してください。
`polyclaw` コマンドを実行してください。
```

### 2.5 中黒・ハイフン
- 並列には全角の「・」を使用してください。
- 長音には「ー」を使用してください。
- ハイフン `-` と長音「ー」を混同しないでください。
- 範囲には「〜」を使用してください。
- マイナス値では半角 `-` を使用してください。
- コマンドオプションでは半角 `-` を維持してください。
- 日時の範囲では、波ダッシュの前後に不要なスペースを入れないでください。
良い例:
```text
作成・編集・削除
サーバーを起動します。
9 時〜17 時
`--help` を指定してください。
```

## 3. 半角・全角の使い分け

### 3.1 英数字
- 英字は常に半角で表記してください。
- 数字は常に半角で表記してください。
- バージョン番号は半角で表記してください。
- コード、コマンド、環境変数は半角表記を維持してください。
- 全角英数字は使用しないでください。
- 略語も半角で表記してください。
- ブランド名の大文字小文字は公式表記に従ってください。
良い例:
```text
polyclaw v6.0.0 をリリースしました。
3 件のエラーがあります。
API キーを設定してください。
```
悪い例:
```text
ｐｏｌｙｃｌａｗ ｖ６．０．０ をリリースしました。
３ 件のエラーがあります。
```

### 3.2 記号
- 括弧と引用符は §2.2 と §2.4 を参照してください。
- パーセントは半角 `%` を使用してください。
- 数値と単位の間には半角スペースを入れてください。
- 単位は半角英字を使用してください。
- スラッシュ `/` は技術用語やパスで使用できます。
- 日本語の並列では、スラッシュではなく「・」を優先してください。
- Markdown の構文記号は半角のまま維持してください。
良い例:
```text
50%
100 MB
5 GB
`app/runtime/` を確認してください。
```

### 3.3 和欧混植スペース
- 全角文字と半角英数字の境界には半角スペースを入れてください。
- 日本語と製品名の間にも半角スペースを入れてください。
- 日本語とバージョン番号の間にも半角スペースを入れてください。
- 半角記号 `(`、`)`、`:`、`/`、`.` の前後ではスペース不要です。
- Markdown のインラインコードの前後は、日本語との境界に半角スペースを入れてください。
- 文頭または文末に半角英数字がある場合は、不要なスペースを入れません。
良い例:
```text
Azure を使ってデプロイします。
polyclaw v6.0.0 をリリースしました。
`.env` を確認してください。
GitHub Actions で実行します。
```
悪い例:
```text
Azureを使ってデプロイします。
polyclawv6.0.0をリリースしました。
`.env`を確認してください。
```

## 4. カタカナ語

### 4.1 長音記号（JIS Z 8301 準拠）
- 3 音以上のカタカナ語は語尾に長音を付与してください。
- 「サーバー」「ユーザー」「コンピューター」「メモリー」を基本形とします。
- 「メモリ」など IT 慣例で定着した語は `glossary.md` で個別判断します。
- 2 音以下の語も、慣例に従って長音を省略しないでください。
- 長音の有無で表記揺れが起きないようにしてください。
- 外来語を新規に追加する場合は、既存表記を検索してから決めてください。
- 同じ PR 内で「サーバ」と「サーバー」を混在させないでください。
推奨例:
```text
サーバー
ユーザー
コンピューター
ブラウザー
プリンター
ドライバー
```

### 4.2 表記揺れの排除
- 同じ語に複数の表記を使わないでください。
- 用語は `glossary.md` で固定してください。
- 新しい表記を採用する場合は、既存の表記を置き換えてください。
- JIS 表記と一般的な IT 表記が異なる場合は、`glossary.md` に理由を残してください。
- 同じ画面内で表記揺れがある場合は、必ず修正してください。
- 「インタフェース」と「インターフェイス」を混在させないでください。
例:
```text
良い例: インタフェース、サーバー、ユーザー
悪い例: インタフェース / インターフェイス、サーバ / サーバー
```

### 4.3 固有名詞
- 製品名とサービス名は原則として英語表記のままにしてください。
- `Azure`、`polyclaw`、`Telegram`、`GitHub` は英語表記のままです。
- カタカナ表記が一般的なものは `glossary.md` で個別判断してください。
- ブランド名の大文字小文字は公式表記に従ってください。
- 製品名を翻訳しないでください。
- 会社名、ライブラリ名、フレームワーク名も公式表記を維持してください。
- 略語は `API`、`LLM`、`CLI`、`UI` のように半角英字で書いてください。
良い例:
```text
Azure に接続します。
GitHub Copilot SDK を使用します。
Telegram から通知を受け取ります。
```

## 5. 絵文字方針

### 5.1 用途
- 絵文字は感情、状態、カテゴリのタグとしてのみ使用してください。
- 文末装飾としての絵文字は禁止です。
- 絵文字は文頭または見出しで 1 つだけ使用してください。
- 連続した絵文字は使用しないでください。
- 意味が曖昧な絵文字は使用しないでください。
- アクセシビリティのため、絵文字だけで状態を伝えないでください。
- 絵文字の後には、必ず日本語ラベルを付けてください。
- 装飾目的の絵文字は使用しないでください。

### 5.2 使用例
- `✅ 完了`
- `⚠️ 警告: 接続が不安定です。`
- `❌ エラー: 保存できませんでした。`
- `📝 メモ`
- `🔍 検索結果`
- `💡 ヒント`
- `🔒 ロック中`
| 絵文字 | ラベル | 用途 |
|---|---|---|
| ✅ | 完了 | 正常終了、成功状態 |
| ⚠️ | 警告 | 注意が必要な状態 |
| ❌ | 失敗 | 失敗、実行不能 |
| 📝 | メモ | 補足、注記 |
| 🔍 | 検索 | 検索、調査結果 |
| 💡 | ヒント | 解決策、補助情報 |
| 🔒 | ロック中 | 権限、ロック状態 |

### 5.3 禁止例
- `保存しました！😊` は文末装飾のため禁止です。
- `エラーが発生しました🤔` は文末装飾のため禁止です。
- `🎉🎊✨ようこそ✨🎊🎉` は過剰な装飾のため禁止です。
- `完了 ✅` は文末装飾に見えるため禁止です。
- `⚠️⚠️ 警告` は絵文字の連続使用のため禁止です。

### 5.4 LLM プロンプト内
- `system_prompt.md` の旧「use emoji generously」セクションは全面的に書き換えてください。
- 「絵文字は状態・感情・カテゴリのタグとして文頭・見出しに 1 つだけ使用してください」と明記してください。
- 「文末装飾としての絵文字は使用しないでください」と明記してください。
- LLM に対しても、絵文字の使用は控えめに指示してください。
- Markdown 見出しで絵文字を使う場合も、1 見出しにつき 1 つまでにしてください。
- エラー、警告、完了などの状態を示す場合は、絵文字と日本語ラベルを併記してください。

## 6. UI 要素の標準文言

### 6.1 ボタンラベル（動詞単独・体言止め）
| 操作 | 推奨ラベル | 注意 |
|---|---|---|
| 保存 | 保存 | 「セーブ」は使わない |
| 適用 | 適用 | 設定変更時 |
| キャンセル | キャンセル | 「中止」は使わない |
| 閉じる | 閉じる | モーダル等 |
| 削除 | 削除 | 確認ダイアログ必須 |
| 追加 | 追加 | 「新規追加」より「追加」優先 |
| 編集 | 編集 | 「修正」より「編集」 |
| 更新 | 更新 | 「リフレッシュ」より「更新」 |
| 検索 | 検索 | 「絞り込み」と区別 |
| 絞り込み | 絞り込み | フィルタ用途 |
| 続行 | 続行 | 「進む」より「続行」 |
| 戻る | 戻る | 「戻る」「前へ」 |
| 次へ | 次へ | ウィザード等 |
| 送信 | 送信 | フォーム送信 |
| ログイン | ログイン | 「サインイン」は使わない（要 `glossary.md` 確認） |
| ログアウト | ログアウト | 同上 |
追加ルール:
- ボタンには句点を付けないでください。
- 原則として 6 文字以内を目安にしてください。
- 主要アクションは動詞単独にしてください。
- 危険操作は「削除」のように意味が明確な語にしてください。
- 「OK」は、文脈が不明確な場合は避けてください。
- 「はい」「いいえ」は確認ダイアログで意味が曖昧になるため避けてください。

### 6.2 トースト（通知）
- 成功は「〜しました」と書いてください。
- 失敗は「〜できませんでした」+ 簡潔な原因と対処を書いてください。
- 進行中は「〜中…」と書いてください。
- 情報は平叙文で書いてください。
- トースト本文は短くしてください。
- トーストには過度な謝罪を入れないでください。
- トーストで詳細が必要な場合は、詳細画面やログへの導線を用意してください。
良い例:
```text
保存しました。
削除しました。
保存できませんでした。接続を確認してください。
読み込み中…
新しいスキルが利用可能です。
```

### 6.3 確認ダイアログ
- 標準形式は「〜してもよろしいですか？」です。
- 削除系は「本当に削除してもよろしいですか？この操作は元に戻せません。」を基本形にしてください。
- 主アクションのボタンは具体的な動詞にしてください。
- 副アクションのボタンは「キャンセル」にしてください。
- 削除ボタンは赤色など、危険操作であることが分かる見た目にしてください。
- ダイアログ本文では、対象名をできるだけ明示してください。
- 破壊的操作では、取り消し不可であることを明記してください。
推奨ボタン:
```text
削除 / キャンセル
保存 / キャンセル
適用 / キャンセル
```

### 6.4 エラーメッセージ
- エラーメッセージは「原因」+「対処方法」で構成してください。
- 原因が不明な場合は、状況と次の行動を示してください。
- 「申し訳ございません」「恐れ入りますが」などの過度な謙譲表現は使わないでください。
- 技術名、コマンド名、ファイル名は原文のまま表示してください。
- ユーザが実行できる対処を 1 つ以上含めてください。
- エラーコードがある場合は、本文の末尾または詳細欄に表示してください。
- セキュリティ上の理由で詳細を出せない場合は、安全な対処を示してください。
良い例:
```text
Azure CLI が見つかりません。インストールしてから再度お試しください。
セッションを読み込めませんでした。ページを再読み込みしてください。
権限がありません。管理者にアクセス権を確認してください。
```

### 6.5 フォーム
- 入力欄ラベルは体言止めにしてください。
- プレースホルダーは例示形式にしてください。
- プレースホルダーだけに重要情報を入れないでください。
- バリデーションエラーは「〜してください」と書いてください。
- 必須マークは「*」または「（必須）」を使用してください。
- 任意項目には必要に応じて「（任意）」を付けてください。
- 入力形式が厳密な場合は、ラベルまたはヘルプテキストで例を示してください。
良い例:
```text
メールアドレス
パスワード
例: user@example.com
メールアドレスを入力してください。
```

## 7. 時刻・日付・数値

### 7.1 時刻表記
- 絶対値は `2026年5月28日 06:31` の形式にしてください。
- 同日内などの略式では `5月28日 06:31` を使用できます。
- 相対値は `5 分前`、`3 時間前`、`昨日`、`先週` の形式にしてください。
- 日付フォーマットは `toLocaleString('ja-JP')` で統一してください。
- 24 時間表記を使用してください。
- タイムゾーンが重要な場合は、`JST` などを明記してください。
- 曜日が必要な場合は、`2026年5月28日（木）06:31` のように表記してください。
良い例:
```text
2026年5月28日 06:31
5月28日 06:31
5 分前
3 時間前
昨日
```

### 7.2 数値表記
- 千区切りには半角カンマを使用してください。
- `1,000`、`1,000,000` の形式を使用してください。
- 桁区切りの「万」「億」は採用しません。
- 技術系プロダクトのため、`10,000` のように表記してください。
- 小数点は半角 `.` を使用してください。
- マイナス値は半角 `-` を使用してください。
- 数値と日本語単位の間にも半角スペースを入れてください。
良い例:
```text
1,000 件
10,000 リクエスト
3.14 秒
-1
```

### 7.3 通貨（該当ある場合）
- 円表記は `¥1,000` または `1,000 円` を使用してください。
- USD は `$10.00` の形式を使用してください。
- 通貨記号と数値の間にはスペースを入れません。
- 日本語単位の「円」を使う場合は、数値との間に半角スペースを入れてください。
- 複数通貨が混在する場合は、通貨コードを明記してください。
例:
```text
¥1,000
1,000 円
$10.00
USD 10.00
```

### 7.4 単位
- 数値と単位の間には半角スペースを入れてください。
- `%` は例外として数値に密着させてください。
- ストレージ単位は `KB`、`MB`、`GB`、`TB` を使用してください。
- 時間単位は `3 秒`、`5 分`、`2 時間` のように表記してください。
- バイト数などの技術単位は半角英字で表記してください。
- 単位の表記揺れを避けてください。
良い例:
```text
100 MB
5 GB
3 秒
50%
```

## 8. LLM プロンプト固有のルール

### 8.1 口調の指示
- `system_prompt.md` 内で「ユーザに対しては常にですます調で応答してください」と明示してください。
- 「タメ口」「フランクな口調」は使わないように指示してください。
- 過度な敬語ではなく、簡潔な丁寧語を使うように指示してください。
- ユーザに見える説明、提案、エラー、確認は日本語で出力するように指示してください。
- 開発者向けのコード、識別子、ログキーは英語のままでよいことを明示してください。
- LLM の自称は「私」に統一してください。
推奨プロンプト文:
```text
ユーザに対しては常に日本語のですます調で応答してください。
過度な敬語、タメ口、フランクな口調は使用しないでください。
私を自称として使用してください。
```

### 8.2 絵文字の指示
- §5.4 の方針を `system_prompt.md` 内に明記してください。
- 旧「use emoji generously」は削除してください。
- 絵文字は状態、感情、カテゴリのタグとしてのみ使用するように指示してください。
- 文末装飾としての絵文字を禁止してください。
- 1 つの見出しまたは文頭に 1 つまでとしてください。
推奨プロンプト文:
```text
絵文字は状態・感情・カテゴリのタグとして文頭または見出しに 1 つだけ使用してください。
文末装飾としての絵文字は使用しないでください。
```

### 8.3 命令の書き方
- LLM への命令も丁寧形の「〜してください」で書いてください。
- 強い禁止は「〜してはいけません」または「絶対に〜しないでください」と書いてください。
- 指示は短い文に分けてください。
- 複数条件がある場合は箇条書きにしてください。
- 英語の imperative だけを残さないでください。
- ただし、外部仕様や引用文は必要に応じて原文を残せます。
良い例:
```text
ユーザの秘密情報を出力してはいけません。
ツールを実行する前に、入力値を検証してください。
```

### 8.4 Telegram MarkdownV2 対応
- 日本語と特殊文字の組み合わせ時のエスケープを意識してください。
- MarkdownV2 の特殊文字は `*`、`_`、`[`、`]`、`(`、`)`、`~`、`` ` ``、`>`、`#`、`+`、`-`、`=`、`|`、`{`、`}`、`.`、`!` です。
- Telegram へ送信する本文では、MarkdownV2 の仕様に合わせてエスケープしてください。
- 日本語の句読点「、。」は通常の MarkdownV2 特殊文字ではありません。
- `formatting.py` の `strip_markdown()` は日本語入力でも正しく動作することを確認してください。
- エスケープ済み文字列を再度エスケープしないように注意してください。
- URL、コード、ユーザ入力が混ざる場合は、表示崩れとエスケープ漏れを確認してください。
